# ewaste-benchmarks
This repository contains code for benchmarks to be tested on a cell phone e-waste server prototype. Benchmark 1 is a task built around researchers' interests in **privacy preservation** of data subjects. Benchmarks 2-4 are designed to emulate social science research interests in understanding statistical relationships among variables in a dataset. Different statistical analysis techniques require varying degrees of computation depending on model complexity. We provide benchmarks for three common statistical analysis techniques: training a computationally intensive random effects model, training a simpler logistic regression model, and inference class labels using a trained logistic regression model. Benchmarks 5-8 replicate tasks that researchers might use to engage in exploratory data analysis: researchers frequently use topic modeling to examine common themes and topics across large text corpora. Topic models may be selected over supervised models when the topics of interest are not a priori known by the researcher. We provide benchmarks for four different topic modeling tasks: LDA topic model training, LDA topic model inference, BERTopic model training, and BERTopic model inference.

# Datasets
## Dataset 1: Federal Office Candidates for 2024 Election Cycle
This dataset contains all candidates for federal office during the 2024 election cycle. It contains their posts across 10 different social media platforms: Facebook, Instagram, Twitter/X, Threads, Tiktok, YouTube, Gettr, Rumble, Telegram, and Truth Social from January 1, 2023 until December 31, 2024. For candidate accounts, candidates were collected throughout 2023 and 2024. Using ballot data to draw the initial list of candidates, research assistants searched for candidate accounts on each platform, identifying both the account associated with the campaign and the office account for incumbents. For each candidate’s account, the posts are collected through the Junkipedia platform, an online monitoring tool created by the National Conference on Citizenship. Junkipedia collects posts for each candidate for each platform on a daily basis, so each post is collected within 24 hours of when it was created by the post author. This data collection consists of 3,321,323 posts by 1,758 candidates across the ten platforms listed above. We reuse these data for Benchmarks 1 and 2. The data collection is accessible via the following data repository permalink: https://doi.org/10.3886/ICPSR300490.V2.

## Dataset 2: Tweets from U.S. Congress
Using the Twitter Search API, Hemphill et al. collected all tweets posted by official Member of Congress (MC) accounts (voting members only) during the 115th U.S. Congress which ran January 3, 2017 to January 3, 2019. They identified MCs' Twitter usernames by combining the lists of MC social media accounts from the United States project (Congress-Legislators, n.d.), George Washington Libraries (Littman, 2017), and the Sunlight Foundation (Sunlight Foundation, n.d.). Throughout 2017 and 2018, Hemphill et al. used the Twitter API to search for the usernames in this composite list and retrieved the accounts' most recent tweets. Their final search occurred on January 3, 2019, shortly after the 115th U.S. Congress ended. In all, the authors collected 1,485,834 original tweets (i.e., excluding retweets) from 524 accounts. The accounts differ from the total size of Congress because the authors included tweet data for MCs who resigned (e.g., Ryan Zinke) and those who joined off cycle (e.g., Rep. Conor Lamb); authors were also unable to confirm accounts for every state and district. We reuse this dataset for benchmarks 4 and 5. The dataset is accessible via the following GitHub repository link: https://github.com/casmlab/modeling-political-attention/tree/master/data/congress_115.

Russell et al. collected and labeled 59,826 original tweets (i.e., retweets excluded) made by the U.S. Senate during the first six months of the 113th and 114th Congresses (Russell, 2017, 2018): 39,704 tweets labeled with codes from the Comparative Agenda Project’s (CAP’s) codebook (Jones et al., 2023) and  20,122 labeled as not-policy tweets. In their supervised model development process (task 5), Hemphill et al. (2020b) found that using Russell’s dataset as-is resulted in an imbalanced training dataset, so selected only a subset of over-represented not-policy tweets to improve model training. We reuse Hemphill et al.’s final balanced training corpus of 41,716 labeled tweets (39,704 policy tweets and 2,012 not-policy tweets) for bechmarks 3 and 6. The dataset is accessible via the following GitHub repository link: https://github.com/casmlab/modeling-political-attention/tree/master/data/russell/russell_processed_0.9.csv.gz.

## Dataset 3: Stack Exchange
Stack Exchange is a social media platform that consists of 184 question and answer communities such as Stack Overflow, Astronomy, and others. Stack Exchange users committed to the preservation of their communities of knowledge regularly archive datasets of public content from Stack Exchange. We use a subset of the dataset originally collected and uploaded to the Internet Archive on January 6, 2026 by Stack Exchange user SakuraKawaii (original dataset available via the Internet Archive link here: https://archive.org/details/stackexchange_20251231). The subset we use contains details about 87,720 comments posted to the Astronomy Stack Exchange community between September 24, 2013 and December 31, 2025, with 6,795 unique users represented as commenters. We use this dataset for benchmarks 7-8. This data subset is available at the following link  (**NOTE: This is a link to a direct download of the compressed data subset. Its compressed size is 56.6mb)**: https://archive.org/download/stackexchange_20251231/stackexchange_20251231/astronomy.stackexchange.com.7z.


# Benchmarks
## Benchmark 1: Privacy Preservation
### Synthetic data generation (or inference) using Llama LLM 
For this benchmark, we will create a synthetic dataset from an existing social media dataset. LLMs are particularly well-suited for this task since they generate text that is more coherent and human-like than their predecessors. This is a key feature for creating synthetic social media data since the synthetic data should appear similar in content and structure to the original dataset. We use **Dataset 1** for this benchmark (see **Dataset 1** above for access instructions). For each text sample in the dataset, we generate a synthetic sample for that text using Llama (or Ollama gemma3:4b) models. The creation of synthetic samples for these texts prevents the ability to reverse search for a text, but also makes it easier to reuse or reproduce research from those original materials. Code for this benchmark is available in the file '01_synthetic_data.py' (language: Python). Once the data are downloaded (see **Dataset 1** above for instructions on access), the code can be run by entering `python 01_synthetic_data.py --input_file [location]` into your command line interface. 

## Benchmark 2: Statistical Analysis
### Understand relationships between variables by training computationally intensive random effects model 
Random effects models, or linear regression models with random effects, are computationally intensive applications of regression that researchers use. We will train a random effects model on the 3.2m social media posts dataset (see **Dataset 1** above for access instructions), predicting engagement as a function of party, platform, and post topic. For this regression model, we will add a random effect for the politician, allowing for different intercepts for each politician. This results in around 3k intercepts for the model, resulting in a model that takes longer to fit. Code for this benchmark is available in the file '02_random_effects.R' (language: R).
